# IRIX COST — версия для ККЗМ

Файл: `index.html` (в репозитории также опубликован на GitHub Pages) — открывается прямо в браузере, установка не нужна.

## Что это

Приложение для расчёта себестоимости и калькуляции на основе трёх выгрузок из 1С:
- спецификации (состав изделий),
- закупочные цены,
- продажи.

Все данные загружаются через интерфейс приложения (три зоны загрузки) и после этого остаются в кэше браузера (localStorage) — при следующем открытии этого же файла в этом же браузере подгружать заново не нужно.

## Что было не так и что поправлено

### 1. Спецификации ККЗМ не читались вообще (0 позиций)

В выгрузке спецификаций у ККЗМ 1C переиспользует одну и ту же колонку под имя изделия и под имя компонента. Старый код различал строку-изделие и строку-компонент по номеру колонки, а раз колонки совпали — вообще не находил строк-изделий: спецификации грузились пустыми, хотя приложение никакой ошибки не показывало.

Добавлена отдельная ветка разбора: когда колонка имени совпадает, тип строки определяется по содержимому колонки количества (у компонента там число, у изделия — текст вида «Спецификация …»).

Результат на ваших файлах: 398 изделий, 1108 компонентов (было 0/0).

### 2. Себестоимость считалась в тысячи раз завышенной (кг вместо тонн)

Часть материалов (листовой и трубный прокат) в спецификации указана в **кг**, а закупочная цена в 1С привязана к **тонне** — так этот металлопрокат закупается и оценивается. Например, «Труба 108*4*12000» стоит 56 656 ₽/т, а по рецепту на одно изделие уходит 0,667 кг — то есть реальная стоимость этой части ≈ 37,8 ₽, а не 37 789 ₽, как считало приложение раньше.

1С сама подсказывает нужный коэффициент прямо в названии единицы измерения компонента: «кг (0,001 т)» значит 1 кг = 0,001 т, то есть искомая цена — за тонну. Расчёт теперь автоматически распознаёт такую подсказку в скобках (в любом виде, включая «кг (0,001 усл. т)» — встречается у труб другого диаметра) и переводит количество в единицу, за которую фактически указана цена, прежде чем умножать на цену.

Результат на ваших файлах:

| | Было | Стало |
|---|---|---|
| Выручка | 19,1 млн ₽ | 19,1 млн ₽ |
| Себестоимость | 4038,0 млн ₽ | 4,08 млн ₽ |
| Маржа | −4018,9 млн ₽ (−21055 %) | +15,0 млн ₽ (+79 %) |

Второе число выглядит куда правдоподобнее для этого бизнеса.

## На что обратить внимание

Часть материалов, встречающихся в спецификациях (в основном не самый ходовой листовой/трубный прокат), не находит цены в переданной выгрузке закупок — видимо, закупается отдельным каналом или в другом периоде. Это не баг приложения, а особенность данных: по этим позициям расчёт покажет цену «none», пока не появится источник цены (закупка, остатки или вручную через справочник цен).

## Как пользоваться

1. Откройте `index.html` в браузере (или сайт на GitHub Pages).
2. Загрузите по очереди три файла в соответствующие зоны: спецификации, закупочные цены, продажи.
3. Приложение само посчитает калькуляцию и сохранит загруженные данные в кэше браузера.

## Если что-то опять посчитается неправдоподобно

Первый сигнал — сравнить итоговую себестоимость с выручкой в шапке: если себестоимость на порядки больше выручки, это почти всегда единица измерения (как в этот раз), а не ошибка в самих ценах. Пришлите файлы или скриншот с примером — поправим.
